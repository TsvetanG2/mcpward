# Security detector corpora

Run by `test/corpus.test.ts`. They measure what the security detectors (`src/checks/security.ts`, `src/checks/heuristics.ts`) miss and what they wrongly flag. They do not change the detectors.

## `evasion/`

One JSON file per case:

| Field        | Meaning                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------ |
| `category`   | `homoglyph`, `split`, `zero-width`, `encoding`, `markdown`, `language`, `placement`, or `benign` |
| `technique`  | What the case does                                                                               |
| `shouldFlag` | `true` for a hostile tool, `false` for a benign near-miss                                        |
| `knownGap`   | Present when the detectors get the case wrong today, with the reason                             |
| `tool`       | The tool definition, as `tools/list` returns it                                                  |

A case with `knownGap` runs as `it.fails`. When a detector change fixes it, the test turns red: remove `knownGap` from the case (in the generator) and add a CHANGELOG note.

The files are generated by `scripts/generate-evasion-corpus.mjs`. Change cases there and rerun it, so invisible and look-alike characters stay readable. Those characters are written as `\uXXXX` escapes in the JSON.

## `registry-clean/`

Real tool definitions. None of them should produce a security finding. Definitions that are flagged today are listed in `known-false-positives.json` with the rule ids and a reason, and the test asserts exactly those ids.
